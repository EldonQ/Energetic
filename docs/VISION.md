# Energetic · 回声美术馆 — 产品愿景与开发计划书

> 版本：v1.0（2026-07）
> 状态：路线图执行中 — Phase 0 进行中
> 本文档是项目的最高层指引：所有功能取舍以此为准。

---

## 一、愿景（一句话）

**任何声音——你的歌、你的嗓子、你的现场——都能立刻变成一座发光的美术馆。**

Energetic 不是一个"音乐可视化播放器"，而是一个**声音的情绪空间生成器**：
它把"听歌"变成独处的仪式，把"演唱"变成自我表达的艺术品，把"现场"变成群体情绪的可视化。

---

## 二、现状诊断（为什么要走向这个愿景）

### 2.1 已有的资产

| 资产 | 说明 |
|------|------|
| 六件可视化作品 | 层理 / 巨石 / 水银 / 晶体 / 高度场 / 尘球，各自独立的物质隐喻与参数体系 |
| 实时音频特征管线 | Web Audio → FFT → bassEnv / midEnv / trebleEnv / beatPulse，逐帧驱动 GPU 粒子与 shader |
| 美术馆级美学 | 全站黑底单色、雕刻字、档案化措辞——克制即风格 |
| 零安装交付 | 纯前端静态站，一个 URL 在任何设备任何屏幕上即开即用 |
| 歌词系统 | LRC 解析 + 卡拉OK填充 + 极简字幕（配菜原则：永不喧宾夺主） |

### 2.2 直面的问题

1. **"看了也就看了"**：品类既视感（音乐可视化 = 已知盒子）+ 工艺不可读（克制的
   品味大众看不见）+ 个人相关为零（访客在参观别人的收藏）+ 高潮藏在 40 秒后。
2. **部署是死界面**：版权音频不入库，GitHub Pages 上曲库为空——线上站点向每个
   访客证明"这个项目不能用"。
3. **语义上拒绝未来**："已封存"的档案馆隐喻是句号，产品语言里没有参与的开口。

### 2.3 破局的核心判断

- 惊艳公式 = 陌生感 × 可读性 × 个人相关 × 即时兑现。现有形态四项皆弱。
- **唯一能翻盘的杠杆是"把观众变成当事人"**：让用户的声音、用户的现场成为
  驱动源，个人相关从 0 到满格。
- 黑底 + 单色亮粒子的版式，恰好是投影场景的物理最优解（投影黑色 = 不打光，
  亮粒子投在墙上 = 悬浮的发光体）。现有美学与 live 方向天然契合。

## 三、终极形态：一个内核，三种模式

```
                    ┌─────────────────────────────┐
                    │   AudioEngine（源抽象层）      │
                    │  文件源 | <audio>元素 | 麦克风  │
                    └──────────────┬──────────────┘
                                   │ 统一特征管线
                                   │ bass/mid/treble/beat
                    ┌──────────────┴──────────────┐
                    │     六件可视化作品（零改动）    │
                    └──────────────┬──────────────┘
              ┌────────────────────┼────────────────────┐
        ┌─────┴─────┐        ┌─────┴─────┐       ┌──────┴──────┐
        │ 档案馆模式  │        │  演唱模式   │       │  现场模式    │
        │ (现有形态)  │        │ (麦克风参与) │       │ (大屏演出壳) │
        └───────────┘        └───────────┘       └─────────────┘
```

### 3.1 档案馆模式（Museum）— 现有形态，持续打磨

- 定位：独处的听歌仪式。策展式曲库 + 歌词配菜 + 参数面板。
- 角色：产品的"门面"与美学基准，所有新模式共享它定下的视觉语言。

### 3.2 演唱模式（Voice）— 把观众变成乐器

- **体验**：接入麦克风，你的声音实时撕裂尘球 / 点燃晶体 / 掀起高度场。
  喊得越狠撕得越开——情绪不再是接收的，是发出的。
- **情绪价值**：声音是最原始的自我表达。对着麦克风一句副歌，看见墙上的
  粒子随自己炸开——这是可分享的瞬间（天然短视频素材），也是酒吧场景里
  的集体仪式（drop 时全场喊，大屏炸裂 = 群体情绪共振的可视化）。
- **明确不做**：卡拉OK打分。这里卖的是"你的声音成为艺术品"，不是"你唱得
  准不准"。
- **演进方向**（第一版之后）：轻量音高检测（自相关法），音高 → 色温/形态
  映射，从"音量驱动"升级为"旋律驱动"。

### 3.3 现场模式（Live）— 零操作的氛围系统

- **定位**：不做 VJ 工具（Resolume/TouchDesigner 的领地，追不上也不该追）。
  目标是**"没有 VJ 的场所"**：中小酒吧、咖啡馆夜场、街边快闪、私人派对——
  想要"大屏放点有格调的、跟着现场音乐动的东西"，但雇不起 VJ 也不会装
  专业软件的场所。
- **卖点**：一个 URL + 一台任意电脑 = 零操作的氛围系统。浏览器即插即用
  是唯一且真实的护城河。
- **输入**：环境麦克风（第一阶段，与演唱模式共享通路）→ line-in 声卡
  直连 DJ 台（专业阶段，信号干净、低频准确）。
- **形态**：Performance 壳 —— 全屏零 UI、光标隐藏、场景自动轮换或热键
  切换（1-6 已有）、长时运行稳定（WebGL context lost 恢复、内存平稳）。
- **场景畅想**：
  - 酒吧砖墙投影：黑底不打光，白色粒子悬浮在砖缝间呼吸；
  - livehouse 大屏：副歌 drop 全场齐喊，尘球在 12 米宽的 LED 上炸开；
  - 街边夜间投影：路人驻足，对着雨棚下的麦克风喊一嗓子，楼面亮起。

## 四、产品原则（不可妥协项）

1. **黑底单色，克制即风格**——任何新功能不得引入彩色渐变、圆角卡片式
   "产品感" UI；美术馆的庄重感是品牌本体。
2. **可视化是主体，一切皆配菜**——歌词、HUD、控件永不喧宾夺主；
   Performance 壳更是零 UI。
3. **零安装、零操作**——任何新能力必须保持"一个 URL 即开即用"；
   宁可砍功能，不加安装步骤。
4. **联觉必须诚实**——视觉响应必须来自真实音频特征（频段能量/节拍），
   禁止装饰性假动画；用户的身体听到的和眼睛看到的必须是同一件事。
5. **版权红线**——公开部署只含免版权/自有授权音频；商业曲目永远只存在
   于本地开发环境。

## 五、技术架构演进

### 5.1 输入源抽象（演唱模式与现场模式的共享地基）

现状：`AudioEngine` 的唯一源头是 `<audio>` 元素（`MediaElementAudioSourceNode`）。

改造：抽象出 `AudioSource` 接口，三个实现——

| 源 | 节点 | 用途 |
|----|------|------|
| ElementSource | MediaElementAudioSourceNode | 现有曲库播放（档案馆模式） |
| StreamSource | MediaStreamAudioSourceNode | 麦克风 / line-in（演唱、现场模式） |
| FileSource（远期） | 同 ElementSource + objectURL | 拖入本地文件（暂缓开发） |

特征提取管线（FFT → bass/mid/treble/beat）与六个可视化场景**零改动**——
它们只消费特征，不关心声音从哪来。

### 5.2 麦克风的三个技术红线

浏览器默认为语音通话优化，对音乐可视化是灾难，`getUserMedia` 必须显式关闭：

```
audio: {
  echoCancellation: false,   // 回声消除会吃掉音乐成分
  noiseSuppression: false,   // 降噪会抹掉高频细节
  autoGainControl: false,    // AGC 会压平动态——bass 呼吸、beat 冲击全没
}
```

其余约束：
- 麦克风信号只进分析器、不进扬声器输出——纯视觉回路，无啸叫风险；
- HTTPS 必需（GitHub Pages 天然满足）+ 用户手势触发；
- 权限被拒时优雅降级回档案馆模式，给一行雕刻字提示。

### 5.3 Performance 壳（现场模式的外衣）

- 入口：URL 参数（如 `?mode=live`）或热键，不新增页面路由；
- 全屏 API + 光标自动隐藏 + 全部 HUD/控件卸载；
- 场景自动轮换（可配置间隔，节拍感知的切换时机）；
- 长时稳定性：WebGL context lost 监听与重建、粒子缓冲区复用、
  连续运行 4 小时内存平稳为验收线；
- 投影适配：亮度/对比参数预设（投影仪 gamma 普遍偏灰）。

### 5.4 性能与稳定性基线

- 30000 粒子 @ 60fps（现有尘球基准）在集成显卡上不掉帧；
- 移动端降级策略：粒子数减半、PostFX 关闭；
- 现场模式内存增长 < 50MB / 4小时。

## 六、路线图

### Phase 0 — 部署复活（进行中）

> 让世界能看到。信任基础，一切讨论的前提。

- [x] 诊断：GitHub Pages 曲库为空的根因（版权音频不入库）
- [ ] 白名单两首示范曲入库：`Daylight.mp3`（无 LRC）+ `一路向北.mp3`（含 LRC）
- [ ] CI 构建自动生成只含示范曲的 manifest（插件已支持，验证即可）
- [ ] 线上站点验收：播放、可视化、歌词（一路向北）、双语全链路可用

### Phase 1 — 演唱模式（下一步）

> 把观众变成当事人。个人相关从 0 到满格。

- [ ] `AudioEngine` 输入源抽象（ElementSource / StreamSource）
- [ ] 麦克风接入（三个红线约束 + 权限降级）
- [ ] 模式切换入口（美术馆语言：如"献声" / VOICE，一行雕刻字，不做大按钮）
- [ ] 增益标定：人声动态范围与音乐不同，特征包络参数需单独调校
- [ ] 验收：对着麦克风哼一段，六个场景全部正确响应；关闭麦克风无泄漏

### Phase 2 — Performance 壳

> 让场所能用。商业形态的容器。

- [ ] `?mode=live` 全屏零 UI 壳
- [ ] 场景自动轮换（节拍感知切换）
- [ ] 长时稳定性达标（4 小时验收线）
- [ ] 投影亮度预设
- [ ] 验收：一台电脑 + 家中墙面/电视，连续运行一晚不崩、不卡、不长内存

### Phase 3 — 场地验证与商业探索（远期）

> 用一晚真实试营换取方向确认。

- [ ] 寻找试营场地（酒吧/咖啡馆/有投影仪的空间）——目前无资源，持续留意
- [ ] 试营装备最小集：笔记本（已有）+ HDMI 线 + 场地投影仪/电视 + USB 麦克风
- [ ] 收集真实反应：店主是否愿意常开？客人是否驻足/拍照/参与喊话？
- [ ] 据此决定：B 端氛围引擎（场所订阅/买断）还是 C 端传播玩具（分享物料）

### 暂缓项（明确不做，避免精力分散）

- 拖入本地音频文件（FileSource）——架构预留，暂不开发
- 卡拉OK打分——与产品气质冲突，永不做
- 歌词逐字同步（增强型 LRC）——待歌词数据源解决后再议
- 移动端 App 化——浏览器形态是护城河，不自废武功

## 七、硬件与资源现状

| 项 | 现状 | 缺口与对策 |
|----|------|-----------|
| 开发机 | 一台电脑（现有） | 足够支撑 Phase 0-2 全部开发与家庭墙面验证 |
| 麦克风 | 电脑内置麦克风 | Phase 1 开发够用；试营时建议 USB 电容麦（百元级） |
| 大屏/投影 | 无 | Phase 2 验收可用家中电视/白墙；Phase 3 依赖场地自带 |
| 场地 | 无 | 不阻塞开发；Phase 3 前持续留意朋友/本地资源 |

**原则：硬件缺口不阻塞任何一行代码。** Phase 0-2 的全部产出都能在
一台电脑上开发、验证、演示；场地与设备只在 Phase 3 才成为依赖。

## 八、商业化路径（按确定性排序）

1. **个人品牌资产（当下即成立）**：项目展示的不是"会写 shader"，而是
   "懂克制、懂情绪、懂把技术藏在体验后面"——作品集的品味证明。
2. **B 端氛围引擎（Phase 3 验证后）**：面向无 VJ 场所的订阅/买断。
   交付 = 一个 URL（或本地包）+ 一页设置说明。边际成本趋近于零。
3. **音乐人发行物料（远期分支）**：独立音乐人单曲发行需要 visualizer
   视频，为其生成"专属视觉身份"的工具化服务。
4. **明确放弃**：C 端订阅收费——听歌免费心智太强，付费墙一立情绪就碎。

## 九、风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 版权：商业曲目意外入库/公开 | 高 | .gitignore 白名单制 + 推送前检查；公开部署只含授权音频 |
| 浏览器 AGC 毁掉现场动态 | 高 | 三个约束显式关闭（5.2 节）；试营前实测 |
| 投影环境光洗白画面 | 中 | 亮度预设 + 夜间场景优先；黑底美学天然抗性 |
| WebGL 长时运行崩溃 | 中 | context lost 恢复 + 4 小时验收线 |
| 品类既视感（"又一个可视化"） | 中 | 叙事锚定"演唱参与"与"零操作现场"，不以"可视化"自称 |
| 单人开发精力分散 | 中 | 严格按 Phase 推进；暂缓项清单守门 |

## 十、成功的样子

- **Phase 0**：任何人打开 GitHub Pages 链接，5 秒内听到 Daylight、
  看到尘球呼吸——不再是死界面。
- **Phase 1**：朋友对着你的电脑麦克风喊了一嗓子，看见球体炸开，
  主动问"这是什么？我能再试试吗？"——第一次有人想参与。
- **Phase 2**：家里的电视整晚运行现场模式当氛围灯，你自己都忘了它是
  自己写的。
- **Phase 3**：某家小酒吧的店主说"下周末还能带过来吗？"——第一个
  真实需求信号，商业化讨论从这一刻才有资格开始。
